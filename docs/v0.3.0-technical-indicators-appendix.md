## A. 指标口径推导

### A.1 有效起点（预热期）的推导

记序列在**连续段内**的下标为 `i = 0, 1, 2, …`（`0` 是段首，不是全局首根）。

| 指标    | 有效起点 | 推导                                                                                        |
| ------- | -------- | ------------------------------------------------------------------------------------------- |
| SMA(W)  | `W-1`    | 需要 `W` 个值才能求均值                                                                     |
| EMA(S)  | `S-1`    | 用前 `S` 个值的均值播种，从 `i = S-1` 起输出，`i ≥ S` 递推                                  |
| MACD    | `S+G-2`  | `DIF` 需 `EMA(F)` 与 `EMA(S)` 同时有效 → `S-1`；`DEA = EMA(DIF, G)` 再需 `G-1` 步 → `S+G-2` |
| RSI(N)  | `N`      | 首个 `avgGain = mean(gain[1..N])`，`gain[1] = close[1] − close[0]`，共 `N` 个 → 下标 `N`    |
| BOLL(P) | `P-1`    | 需要 `P` 个值才能求均值与标准差                                                             |
| KDJ(n)  | `n-1`    | `RSV` 需要窗口内 `n` 根的 `high/low`；`K/D` 由 50 播种，`i = n-1` 即首次可算                |
| ATR(N)  | `N`      | `TR_0 = high_0 − low_0`（无前收）；首个 `ATR = mean(TR[1..N])` → 下标 `N`                   |
| OBV     | `0`      | 无窗口、无平滑，段首即可定义                                                                |

### A.2 EMA 的种子：为什么用 SMA 播种而不是段首收盘价

若以段首收盘价 `x[0]` 播种（`EMA[0] = x[0]`），则种子在 `i` 处的权重是 `(1−α)^i`，`α = 2/(S+1)`：

| `S` | `α`   | `(1−α)^(S−1)` | 含义                                       |
| --- | ----- | ------------- | ------------------------------------------ |
| 12  | 0.154 | 0.158         | 第 `S-1` 根输出里仍有 **15.8%** 是任意种子 |
| 26  | 0.074 | 0.146         | 第 25 根输出里仍有 **14.6%** 是任意种子    |
| 60  | 0.033 | 0.135         | 第 59 根输出里仍有 **13.5%** 是任意种子    |

也就是说「预热 `S-1` 根」这个约定**并不能**让段首种子收敛掉——它只是把权衰减到 `e^-2 ≈ 13.5%`
就停了。因此：

1. **改用 SMA 播种**（`EMA[S-1] = mean(x[0..S-1])`，`i ≥ S` 起递推）。首个输出就是那 `S` 个值的
   算术均值，不再是一个说不清来源的数，也不会因为「段首恰好是一根异常大的 K 线」而整体偏移。
2. 这是**对既有 `quant_core.ema` 的有意口径变更**：现实现是 `out[0] = values[0]` 起递推，
   其单测 `test_ema_starts_at_first_value` 会随之更新。变更记入实现记录。
3. `MACD` 的 `DEA = EMA(DIF, G)` 同理：以最初 `G` 个有效 `DIF` 的均值播种。

### A.3 为什么递推指标必须从段首重推，而不能从上一步续算

R-4.2 要求「段内从段首重推」，不是实现偏好。关键在于：**只有 RSI 的递推状态无法从输出反推。**

| 指标    | 递推式                              | 输出本身是否就是完整状态 | 能否从上一行续算 |
| ------- | ----------------------------------- | ------------------------ | ---------------- |
| EMA     | `E_i = α·x_i + (1−α)·E_{i−1}`       | 是（状态 = `E`）         | 能               |
| MACD    | `DIF`/`DEA` 两个 EMA                | 是                       | 能               |
| ATR     | `ATR_i = (ATR_{i−1}(N−1) + TR_i)/N` | 是（状态 = `ATR`）       | 能               |
| OBV     | `OBV_i = OBV_{i−1} ± v_i`           | 是（状态 = `OBV`）       | 能               |
| KDJ     | `K_i = ((kp−1)K_{i−1} + RSV_i)/kp`  | 是（状态 = `K`,`D`）     | 能               |
| **RSI** | 见下                                | **否**                   | **不能**         |

RSI 的递推状态是 `avgGain` 与 `avgLoss` **两个绝对量**，而输出只有它们的比值：

```
RS_i    = avgGain_i / avgLoss_i
RSI_i   = 100 − 100/(1 + RS_i)
avgGain_i = (avgGain_{i−1}(N−1) + gain_i) / N
avgLoss_i = (avgLoss_{i−1}(N−1) + loss_i) / N
```

由 `RSI_{i−1}` 只能得到 `RS_{i−1}`（比值），**得不到 `avgGain_{i−1}` 与 `avgLoss_{i−1}` 各自的
绝对水平**。同一个 `RSI = 50` 可能来自 `(avgGain, avgLoss) = (1, 1)`，也可能来自 `(0.01, 0.01)`，
而下一个值 `(avgGain_i, avgLoss_i)` 依赖绝对水平 → 二者会给出不同的 `RSI_i`。

三条出路与取舍：

| 出路                                  | 结论                                                                     |
| ------------------------------------- | ------------------------------------------------------------------------ |
| 表里多存 `avg_gain` / `avg_loss` 两列 | 可行但丑：表里出现不是指标输出的「递推状态列」，读侧与语义都被污染       |
| 用有限预热窗近似（如 `10×N`）         | **否决**。同一根 K 线今天算和明天算会不同 → 违反幂等与可复现，是静默兜底 |
| **段内从段首重推**                    | **采用**。精确、幂等、无额外状态列；代价是每次重算需读该段全序列，见 A.4 |

因此 R-4.2 不是「为了简单」，而是 RSI 这条约束逼出来的唯一无状态解；顺带让
「段间不递推」成为可能（A.5），增量成本从 O(全历史) 降到 O(所在段)。

### A.4 重算的读代价（为什么向量化全量读是可接受的）

采用段内重推后，每次重算需要读该段的**全部** OHLCV。量级（用 §B 的实测行数）：

| 周期 | 单标的行数 | 需要的列（close/high/low/volume） | 内存     | numpy 计算 10 个行集 |
| ---- | ---------- | --------------------------------- | -------- | -------------------- |
| 15m  | ~216 000   | 4 × 8 B                           | ~6.9 MB  | 毫秒级               |
| 1h   | ~54 000    | 4 × 8 B                           | ~1.7 MB  | 亚毫秒级             |
| 4h   | ~13 600    | 4 × 8 B                           | ~0.4 MB  | 亚毫秒级             |
| 1d   | ~2 300     | 4 × 8 B                           | ~0.07 MB | 亚毫秒级             |

**读是廉价的（15m 单段不到 7 MB），写才昂贵。** 所以设计取「全段读入 + 向量化全量算 + 只
UPSERT 重算起点之后的行」：读 O(段长)、算 O(段长)、**写 O(新增行数)**。

反过来说，这也解释了为什么 1m 不物化（N-2）：1m 单标的 320 万行，同样口径下读 ~100 MB、
算 320 万点，且这些代价要在**每一轮同步**里付。

### A.5 连续段与「跨缺口递推」的坏处（可复现的最小例）

取 `EMA(3)`（`α = 0.5`），派生表里有缺口：

- **A 段**：`close = [10, 10, 10, 10]`
- **缺口**：若干根缺失
- **B 段**：`close = [100, 100]`

| 口径                    | B 段算出的 EMA                                              |
| ----------------------- | ----------------------------------------------------------- |
| **段间不递推（R-4.2）** | B 段独立；`S=3` 但段长只有 2 → 预热未过 → **零行**          |
| 跨缺口递推              | `EMA = 0.5×100 + 0.5×10 = 55`，再 `0.5×100 + 0.5×55 = 77.5` |

跨段递推下，B 段前两根显示 `55 / 77.5` 而不是 `100 / 100`——**用户会读成「有下跌趋势」**，
而真相是 A 段的陈旧状态漏了过来。更糟的是**回补缺口**时：A、B 合并成一段，B 段全部值被重算，
库里的历史指标值被静默改写，界面上没有任何解释。

这与 v0.1.0 R-11.10「缺口不得插值」是同一条精神：**缺口就是噪声，不得跨越。**

### A.6 两处必须择一的口径

**MACD 柱**

| 口径                   | 公式                   | 使用方                  |
| ---------------------- | ---------------------- | ----------------------- |
| 国际（TradingView 等） | `HIST = DIF − DEA`     | **本期采用**            |
| 国内（通达信/同花顺）  | `HIST = 2×(DIF − DEA)` | 不采用；读侧如需自行 ×2 |

两种口径都在用，**必须选一种并写明**。让库里存一个说不清来源的数，比让读侧「自己乘 2」更糟。

**KDJ 分母为 0**

窗口内 `max(high) == min(low)`（横盘）时 `RSV = (close − min)/(max − min)` 分母为 0。
取 **`RSV = 50`**（0–100 标度的中性点）：

- 产生 `NaN` / `Inf` → 违反跨语言契约（README「跨语言契约」第 3 条：不允许 `NaN` / `Infinity`）
- 沿用前值 → 横盘期会被读成「趋势延续」，而真相是**没有信息**
- 取 0 → 被读成「极度超卖」，同样是无中生有

50 是唯一不注入方向的取值。此分支必须有专门用例（AC-1）。

### A.7 OBV 的绝对量语义

`OBV_0 = 0`，之后按涨跌累加成交量。因此：

- 段首一变（例如补了一根更早的 K 线），该段**全部** OBV 值整体平移；
- 不同段之间、不同标的之间的 OBV **绝对值不可比**；
- 只有**相对变化**（斜率、与价格的背离）有意义。

这条必须写进契约（R-1.6），否则读侧很容易把 OBV 当成一个可比量画到同一张图上。

### B.2 指标表的行数模型

指标表的行数 = **行集数 × 每行集的时间点数**，其中「行集」= 一个
`(参数集, 指标)` 组合：

```
15m 单标的行数 = Σ over 参数集 (该周期点数 − 预热期)
```

缺省参数集（R-12.1）的行集数：

| 指标 | 缺省参数集                                | 行集数 |
| ---- | ----------------------------------------- | ------ |
| MA   | `sma(5)`, `sma(10)`, `sma(20)`, `sma(60)` | 4      |
| MACD | `(12, 26, 9)`                             | 1      |
| RSI  | `(14)`                                    | 1      |
| BOLL | `(20, 2000)`                              | 1      |
| KDJ  | `(9, 3, 3)`                               | 1      |
| ATR  | `(14)`                                    | 1      |
| OBV  | 无参数                                    | 1      |
|      | **合计**                                  | **10** |

（EMA 已实现但**不在缺省参数集里**，需要时加一行配置即可，见 R-3.3。）

### B.3 估算

按 §B.1 实测的 ~135 字节/行估算（指标表列数与 `klines_15m` 相当，7–10 列 + 主键前缀索引）：

| 周期     | 单标的点数 | 行集数 | 单标的总行数 | 单标的估算体积   |
| -------- | ---------- | ------ | ------------ | ---------------- |
| 15m      | ~216 000   | 10     | ~2 160 000   | **~292 MB**      |
| 1h       | ~54 000    | 10     | ~540 000     | ~73 MB           |
| 4h       | ~13 600    | 10     | ~136 000     | ~18 MB           |
| 1d       | ~2 300     | 10     | ~23 000      | ~3 MB            |
| **合计** |            |        | **~2.86 M**  | **~386 MB/标的** |

**两标的合计约 772 MB**——与现有 `klines_1m`（826 MB）同量级。

对照：若把 1m 也物化（N-2 已排除）：

| 周期 | 单标的点数 | 行集数 | 单标的估算体积 |
| ---- | ---------- | ------ | -------------- |
| 1m   | ~3 200 000 | 10     | **~4.3 GB**    |

### B.4 体积是**可调的**，不是固定的

体积与行集数线性相关。评审时可按需删减缺省参数集：

- 去掉 `sma(10)` / `sma(60)` → 行集数 10 → 8，体积降 ~20%
- 只保留 `sma(20)` + MACD + RSI → 行集数 3，体积降 ~70%

因此「指标表比 1m 还大」不是必然结论，而是**缺省参数集的直接后果**，这一点必须让评审者看到。

## C. 未来函数：可复现的最小例

### C.1 现模型（`packages/backtest/src/engine.ts:53-56`）

```ts
const signal = strategy.onBar(bar, bars.slice(0, i + 1));  // 看得到 bar i 的 close
if (signal?.side === 'long' && qty === 0 && cash > 0) {
  const fill = buyFill(bar.close);                          // 又用 bar i 的 close 成交
```

**知道收盘价的同时以该收盘价成交。** 两个可测的后果：

| 场景                             | 现模型                                | 修正模型（R-2.3） | 差异                               |
| -------------------------------- | ------------------------------------- | ----------------- | ---------------------------------- |
| `t` 收 100，`t+1` 开 110（跳空） | 成交价 100                            | 成交价 **110**    | **+10%**                           |
| 信号出现在序列**最后一根**       | 以末根收盘开仓，随即被强平（L92-104） | **不产生交易**    | 一笔必亏的往返（2× 手续费 + 滑点） |

第二行尤其说明问题：现模型下「最后一根的信号」必然产生一笔**只赔手续费**的交易——
那是纯粹由模型缺陷制造的噪声，也会污染胜率与盈亏比。

### C.2 为什么不能靠「策略自己小心」规避

`Strategy.onBar(bar, history)` 的签名把 `bar` 与 `history`（含 `bar` 自身）一起给了策略，
而**成交发生在同一根**。也就是说「策略只用已收盘数据」这条纪律再怎么守，
只要成交价取 `bar.close`，未来函数就还在。**必须在引擎层修**，不能靠约定。

### C.3 修正后行为变化的预期范围

| 项                         | 是否变化 | 说明                                         |
| -------------------------- | -------- | -------------------------------------------- |
| 成交价                     | **变**   | `t` 收盘 → `t+1` 开盘                        |
| 交易次数                   | **变**   | 末根信号不再成交                             |
| 收益 / 夏普 / 回撤 / 胜率  | **变**   | 由上面两项传导（期望：略变差——这才是真实值） |
| 绩效指标**口径**           | 不变     | R-8.4：夏普 / 回撤 / 盈亏比定义不动          |
| 命令接口 / 报告路径 / 格式 | 不变     | AC-13 守住                                   |

## D. 增量与幂等的推演

### D.1 重算起点的三种情形

设周期桶宽 `W`，本批聚合在周期 `I` 上触及的桶区间起点为 `b0`：

| 情形             | `b0`           | 重算区间             | 实际写入                         |
| ---------------- | -------------- | -------------------- | -------------------------------- |
| 纯追加（常见）   | 新桶起点       | `[段首, 段末]`       | `[b0+预热, 段末]` = 新桶         |
| 中间缺口被回补   | 缺口所在桶起点 | `[段首, 段末]`       | `[b0+预热, 段末]` = **整条尾巴** |
| 本批该周期无变化 | —              | 不重算（`noChange`） | 无                               |

第二行是代价最大的一种：回补一个久远缺口会重写该段此后全部指标行。这是**正确性要求**——
缺口把段切开了，回补把段合上了，合并后的段本来就应该整体重算。文档必须写明这一点，
否则会被当成性能缺陷（AC-8 专门断言它）。

### D.2 幂等的来源

1. 指标是**纯函数**：同一段输入必得同一段输出，无时钟、无随机、无网络（R-1.2）。
2. 写入是 `UPSERT`，主键 `(symbol, interval, impl_version, 参数…, time)` 覆盖同一格。
3. 值未变时不产生新行。

因此「连续两次补齐，第二次 `upserted = 0`」是可推出的，不是观察出来的（AC-7）。

### D.3 混版为什么必须硬拒绝

`impl_version` 变更后若增量路径继续写：

```
time:  ... 1000  1010  1020 | 1030  1040 ...
ver :  ...    1     1     1 |    2     2 ...   ← 前半段 v1、后半段 v2
```

读侧默认取 `max(impl_version)`，于是**只会读到后半段**；若读侧取「全部」，则两条不同口径的
序列被拼成一条，**看起来完全正常**。两种都不可接受 → `INDICATOR_IMPL_STALE` 硬拒绝（R-4.6 / AC-10）。

## E. 核验 SQL

### E.1 列结构与合作约束逐列核对（AC-2）

用 `information_schema` 断言，而不是把 DDL 再抄一遍。**必须按 `table_schema` 过滤**——
`information_schema` 是全库的，不加过滤会把 `public` 里的同名表捞进来，让列比较假失败
（v0.2.0 测试里已踩过这个坑）。

```sql
SELECT table_name, column_name, data_type, is_nullable, ordinal_position
  FROM information_schema.columns
 WHERE table_schema = current_schema()
   AND table_name LIKE 'indicator\_%'
 ORDER BY table_name, ordinal_position;
```

```sql
-- 每个参数列都必须 NOT NULL 且带 > 0 的 CHECK
SELECT c.table_name, c.column_name, c.is_nullable, ck.check_clause
  FROM information_schema.columns c
  LEFT JOIN information_schema.check_constraints ck
    ON ck.constraint_name = (
         SELECT cc.constraint_name FROM information_schema.constraint_column_usage cc
          WHERE cc.table_schema = c.table_schema AND cc.table_name = c.table_name
            AND cc.column_name = c.column_name LIMIT 1)
 WHERE c.table_schema = current_schema() AND c.table_name LIKE 'indicator\_%'
   AND c.column_name IN ('impl_version','window','period','fast','slow','signal',
                         'k_period','d_period','n','k_milli')
 ORDER BY 1, 2;
```

```sql
-- interval 的允许集合必须不含 1m
SELECT pg_get_constraintdef(oid) FROM pg_constraint
 WHERE conrelid = 'indicator_ma'::regclass AND contype = 'c';
```

### E.2 预热边界核对（AC-5）

对每个 `(symbol, interval, 参数集)`，指标行的 `min(time)` 必须等于「所在段首 + 预热期×W」。

```sql
WITH w AS (SELECT 900000::bigint AS w)                     -- 15m
SELECT m.symbol, m.window,
       min(m.time) AS 指标首行,
       (SELECT min(k.time) FROM klines_15m k WHERE k.symbol = m.symbol) AS 派生首行,
       (min(m.time) - (SELECT min(k.time) FROM klines_15m k WHERE k.symbol = m.symbol))
         / (SELECT w FROM w) AS 实际跳过根数,
       m.window - 1 AS 期望跳过根数
  FROM indicator_ma m
 WHERE m.kind = 'sma'
 GROUP BY m.symbol, m.window
 ORDER BY 1, 2;
-- 「实际跳过根数」必须 >= 「期望跳过根数」；相等当且仅当首段长度足够
```

### E.3 段内不得跳行（AC-5 / AC-8）

期望行数 = 对派生表的每个连续段求和 `max(0, 段长 − 预热期)`：

```sql
WITH w AS (SELECT 900000::bigint AS w),
seg AS (
  SELECT symbol, time,
         sum(brk) OVER (PARTITION BY symbol ORDER BY time) AS seg_id
    FROM (
      SELECT symbol, time,
             CASE WHEN time - lag(time) OVER (PARTITION BY symbol ORDER BY time)
                       = (SELECT w FROM w)
                  THEN 0 ELSE 1 END AS brk
        FROM klines_15m
    ) s
),
seglen AS (SELECT symbol, seg_id, count(*) AS n FROM seg GROUP BY 1, 2)
SELECT (SELECT coalesce(sum(greatest(0, n - 59)), 0) FROM seglen) AS 期望行数,   -- sma(60) 预热 59
       (SELECT count(*) FROM indicator_ma WHERE kind = 'sma' AND window = 60) AS 实际行数;
```

### E.4 混版检测（AC-10）

```sql
-- 任一行集出现多个 impl_version → 混版
SELECT 'indicator_ma' AS 表, symbol, interval, kind, window, count(DISTINCT impl_version) AS 版本数
  FROM indicator_ma GROUP BY 1,2,3,4,5 HAVING count(DISTINCT impl_version) > 1
UNION ALL
SELECT 'indicator_rsi', symbol, interval, NULL, period, count(DISTINCT impl_version)
  FROM indicator_rsi GROUP BY 1,2,3,4,5 HAVING count(DISTINCT impl_version) > 1;
-- 其余 5 张表同理
```
