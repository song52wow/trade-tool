# @trade-tool/sync

常驻行情同步守护进程（R-17 … R-22）。

- `src/primitives.ts` — 控制原语：`addSymbol` / `removeSymbol` / `listSymbols` /
  `start` / `pause` / `resume` / `getStatus` / `getSummary`。**全部幂等、全部类型完整、
  不依赖任何 HTTP 框架**，供控制面直接 import。
  新增标的默认 `paused`，并且在**开启之前**就把首次全量的规模预估写进 `sync_state`
  （`plan_*` 列，迁移 `002`），由 `sync status` 暴露——控制面据此决定要不要开始。
- `src/daemon.ts` — 调度循环：标的集合、生命周期、全局限速、单写者、错误隔离、退避。
  启动时先过 schema 版本闸门；每轮按 `last_run_at` **公平轮转**，并发上限之外的标的不回饿死；
  单标的失败只在它自己的状态里落地，绝不终止进程。
  **慢标的不堵住别人**：一轮是「**启动**该跑的标的」而不是「等它们跑完」——
  见下面那一节。
- `src/service.ts` — `createSyncService()`：把「原语 + 守护进程 + 连接池」组装起来。
  **控制面与守护进程共享同一个 `SyncControl` 实例**，否则 `resume()` 清不掉守护进程的退避。
- `src/alert.ts` — 同步器自己的故障 → 飞书告警的**转换**（通道仍是 core 那一份）。
  三件事会推：`sync-symbol-error`（某个标的连续失败到上限被钉死）、
  `sync-stopped`（所有在跑的标的都被钉死 = 同步停摆）、`sync-stopped` 的另一条
  （守护进程因全局性错误退出）。见下面那一节。
- `src/main.ts` — 进程入口（`bin: trade-tool-sync`）。配置里的 `sync.symbols` 支持两种写法：
  `"SOLUSDC"`（默认 paused）或 `{ "symbol": "SOLUSDC", "desiredState": "running" }`。

所有写入都经 `@trade-tool/data`，本包**不得**直接连 PG（R-2.4）。

## 慢标的不堵住别人（2026-10-23 修）

### 原来坏在哪

一轮同步 = 把「上次水位 → 现在」的数据**一次拉完**（`batch-size` 只是**写库**的批次大小，
不是拉取上限）。所以一个标的的**首次全量回补**动辄几百页 HTTP 请求，实测一轮 11~15 分钟。

而调度循环原来写成「等这一轮**全部**标的跑完才进下一轮」（`await Promise.all(workers)`），
于是这个慢任务把整个循环钉住：**别的标的十几分钟才被调度一次**。

2026-10-23 在目标机上实测到的样子：BTCUSDT / SOLUSDT 的 1m K 线落后 10~15 分钟
（用户看到的是「同步停在 7 分钟前」），而根因只是**另一个**标的（BNBUSDT）在做它的
首次全量回补。数据没坏、程序没卡死——只是队列被一个慢任务堵住了。

### 现在怎么做的

一轮 = **启动**该跑的标的，然后立刻返回。每个标的各跑各的，跑完自己摘掉并发名额；
循环每 `sync.pollIntervalMs` 扫一次，把空闲名额分给还没跑的标的。

慢标的照旧占着自己的名额（**并发上限依然成立**），但不再挡住别人。

三条要记住的：

- **名额即释放**：任务跑完就从在途表里摘掉，空出来的名额下一轮立刻能用。
- **失败不丢**：任务不再由 `tick()` 等待，失败就拿不到返回值了。单标的失败照旧只写它
  自己的状态；**全局性错误**记进 `fatalError`，循环下一轮检查到就退出——「全局性错误
  必须让进程退出」这条硬约束因此没丢，代价是退出最多晚一个轮询周期（默认 15 秒）。
- **优雅退出**要一并等在途任务（`stop()` 里），否则退出时会留下半途而废的写库事务。

守这个行为的用例在 `apps/sync/tests/lifecycle.test.ts` 的「慢标的不堵住别人」：
一个用例守住「慢的卡着时快的照旧一轮一轮跑」，另一个守住「并发上限没被这次修复废掉」。

## 同步停下来必须有人知道（2026-10-25 补）

### 原来坏在哪

目标机 192.168.1.90 上实测到一次**静默 5 小时 55 分**：

- 三个标的连续失败（出口代理间歇性超时）到 `sync.maxConsecutiveErrors`（默认 5），
  被写成了 `error`，**不再被自动调度**（R-21.3：要有恢复才会再跑）；
- 调度器每 15 秒扫一次、每次都选不出标的，而 `tick()` 对空批次**直接 return、不打日志**；
- 与此同时**心跳照刷**——心跳定时器与调度循环是分开的——控制面因此显示「在线」。

结果就是：一条数据都没进，页面上却是绿的，日志里一行都没有。**没人知道。**

### 现在怎么做的

三件事，缺一不可：

1. **推飞书**（`src/alert.ts`）。三种事会推：`sync-symbol-error`（标的被钉死）、
   `sync-stopped`（停摆，分「全被钉死」与「很久没进展」两种原因）、
   以及守护进程因全局性错误退出。
   通道与去重/冷却仍是 core 那一份（`AlertDispatcher`），**推送失败不影响同步**。
2. **不再静默**。空批次也打一行日志（只在状态变化时打，免得每 15 秒一行）。
3. **心跳不再骗人**。停摆时**停掉**心跳刷新：心跳的职责是回答「有人在干活吗」，
   停摆时没有任何数据会再进，继续刷就是让控制面显示「在线」。
   停掉之后页面按心跳年龄判成 stale，而真正的处置（人工恢复被钉死的标的）
   由飞书那条「同步停摆」告警说清楚。

### 人工恢复

被钉死的标的**不会自己好**：修好原因后，在控制面「标的」页点「恢复」
（`resume()` 会清掉退避与连续失败计数，控制面是它唯一的入口）。
在那之前，它既不会被调度，也不会再失败——**它只是不动了**。
`cli sync status` 能看出哪个标的处于 `error`（CLI **没有**恢复命令，恢复只在控制面）。

### 哪些失败会把标的钉死（2026-10-25 改）

**只有「这个标的有问题」的失败会钉死它**：

| 失败类型                     | 例子                                                            | 会钉死吗                                              |
| ---------------------------- | --------------------------------------------------------------- | ----------------------------------------------------- |
| 交易所明确说不行、数据对不上 | `EXCHANGE_ERROR`、`AGGREGATION_FAILED`、`UNCLOSED_BAR_IN_STORE` | **会**（连续 `sync.maxConsecutiveErrors` 次，默认 5） |
| PG 抖动                      | `DB_CONNECTION_FAILED`、`DB_DEADLOCK`                           | **会**（R-21.6：退避重试，到阈值也停）                |
| **现在连不上**               | **`NETWORK_ERROR`、`RATE_LIMITED`、`EXCHANGE_RATE_LIMITED`**    | **不会**                                              |

为什么把网络类摘出去：出口代理与交易所会**间歇性**抽风。目标机上实测：同一个代理
节点上 `limit=500` 只要 1.9 秒、`limit=100` 却超时 25 秒——是随机的，与请求大小无关。
旧口径下代理抖 5 次就把标的**永久**钉死、要人工点恢复；而代理一恢复，数据本来就能
自己续上。实测就是这么把 BNBUSDT 钉了 15 次、停了 40 分钟没人管。

网络类失败**照样**按指数退避拉长间隔（别去锤交易所），只是不再有「钉死」的副作用。
`sync_state.error_count` 记的是**真错误**的连续次数——它要与「钉死」的判据一致，
也要能在重启后原样恢复。

⚠️ **代价与补救**：网络类不钉死，意味着代理彻底断掉时标的不会被钉死，
「所有标的都被钉死」那条停摆判据也就不触发。所以另有一条判据接手：
**10 分钟内没有任何标的同步成功**（且当前没有在途任务）= 停摆 → 推飞书 + 停心跳。
「有在途任务」不算停摆——首次全量回补实测要十几分钟，那是在干活。

守这些行为的用例在 `apps/sync/tests/alert.test.ts` 与
`apps/sync/tests/lifecycle.test.ts`（「网络错误不算连续失败」那条）。
