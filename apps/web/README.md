# @trade-tool/web — 控制面

HTTP API + 前端看板，把 `apps/cli` 的日常操作变成网页操作（对应设计文档的 R-23 … R-25）。

## 跑起来

```bash
pnpm build                     # 先构建：tsup 出服务端，vite 出前端到 dist/ui
pnpm --filter @trade-tool/web start    # 或 node apps/web/dist/main.js
```

打开 `http://127.0.0.1:8787`。监听地址由 `.env` 的 `TRADE_TOOL_WEB_HOST` / `TRADE_TOOL_WEB_PORT` 决定。

开发时前后端分开跑：终端 A `pnpm --filter @trade-tool/web dev`（tsx watch，8787），
终端 B `pnpm --filter @trade-tool/web dev:ui`（Vite 5173，`/api` 自动代理到 8787）。

## 它和 CLI 的关系

控制面**直接 import** `@trade-tool/sync` 的原语与 `@trade-tool/data` 的查询层，
不 shell out 解析 stdout。守护进程仍然是独立的 `apps/sync` 进程：控制面只写
`desired_state`，由守护进程按 R-19「先落库再生效」响应，两者不需要新的通信机制。

## 五条硬约束

规矩以 AGENTS.md §6.6 为准，这里只列标题与一句说明：

1. **重活儿不阻塞 HTTP** —— 首次全量是几十分钟量级，接口只登记作业并立刻返回 job id
   （R-17.6）。进度每次从 `sync_state` 重读，所以关掉页面、甚至重启进程，进度依然
   与库里的事实一致。
2. **单写者** —— 作业不允许接管 `desired_state = running` 的标的，直接返回 409 并提示
   「请先 pause」——那是守护进程的地盘，两个进程写同一张表会撞单写者锁（R-3.3）。
3. **首次全量必须先算规模** —— `GET /api/symbols/:symbol/estimate` 拿到行数/请求数/权重后
   才允许发起（页面弹确认框），没有「缩短范围」这个选项（R-8.3）。
4. **不假装在同步** —— 「开始同步」只写 `desired_state`，干活的是独立进程 `apps/sync`。
   守护进程离线时页面必须如实显示（横幅 + 卡片 + 按钮标签），三态
   `running` / `stale` / `stopped` 分开报。
5. **K 线只画真实的行** —— `/bars` 是纯读，横轴按时间排，缺一根就是空一根，
   不插值、不拿均价线顶替；非法周期必须 400，**不得静默回落**到 1m。

## 标的详情页上的 Agent 面板（v1.0.0）

`AgentPanel` 显示分析师的三面分数、合成立场 / 信心 / 一致性，
以及交易员算出来的进场 / 仓位 / 止损止盈与「已调整」记录。它挂在标的详情页
（`SymbolDetail`）里，**不另开路由、不另开页面**——报告与方案本就是 per-symbol 的。

数据来自 `GET /api/symbols/:symbol/agent`（只读 PG，不调模型、不出网）。

**批准 / 驳回**走 `PUT /api/symbols/:symbol/agent/plans/:planId`
（body `{status: 'approved' | 'rejected'}`）：

- 批准 / 驳回**都要二次确认**——批准的含义是「这份方案可以变成真实订单」。
- **限价方案不给批准按钮**：限价单可能永远不成交，而不成交的仓位没有止损保护。
  控制面在**批准时**就拒绝并说明原因，而不是批准完再失败。
  「能不能批准」这条判据住在 `packages/core/src/agent-plan.ts`，由**服务端算好**
  随 DTO 传回来（`approvable` / `approvableReason`），页面只负责显示。
  ⚠️ **页面不能 import `@trade-tool/core`**：core 的 barrel 带着 `node:crypto` / `node:fs`，
  浏览器构建会直接失败。前端 import core 只能 import **类型**。
- **「批准」不等于「已经有单下出去」**：自动执行开关关着时 executor 压根不消费方案。
  面板上每种状态都写清了这一点。

⚠️ **`executed` 只能由执行器写**：控制面不能把方案标成「已执行」——
那要真的下过单（有单号、有时刻）。页面点一下就能造出一条「已下单」的假记录，
那是最坏的一种假象。

读取失败必须**常驻可见**（AGENTS.md §5 第 9 条），不能只弹一下 toast。

## 止盈止损面板上的「补挂止盈止损」（v1.3.0）

标的详情页的「止盈止损」区块（`BracketPanel`）上有一个**「补挂止盈止损」**按钮。
它是**人工干预**的入口：自动挂单系统出错（用户数据流断了、私有接口被拒、单被人在
交易所上撤了）之后，仓位会没有保护，而对账只报告不动手。

走 `POST /api/symbols/:symbol/reattach`（body `{dryRun: boolean}`）：

- **先试算再挂**：点一下按钮先发一次 `dryRun: true`，把「要挂哪几张、各多少钱」显示
  出来；用户确认后才发 `dryRun: false` 那一次。条件单是**市价**平仓单，触发价一旦被
  穿过就会立刻把仓位平掉——让人先看清再决定。
- 缺省是**真挂**（`dryRun` 缺省为假）：反过来（缺省不挂）会让「忘了传参数」变成一次
  静默的空操作，而用户以为已经补上了。
- 它是**写操作**，来源校验（`checkOrigin`）照旧；它**只跑一次**，不起守护进程
  （AGENTS.md §6.6 第 2 条）。
- **「拒绝补挂」与「不需要补挂」在页面上是两回事**：前者是「该补但不敢补」
  （比如交易所的仓位数量与本地记录对不上，照记录补可能重复减仓），走 `✘` 红色一行
  显眼显示；后者是「仓位有保护」。DTO 里各用一个字段（`refusal` 与 `details`/`skips`），
  不许混在一起——混了人会以为「不用管」，而那正是最需要人管的时候。
- 「第一段止盈已成交、而库里没记」这件事被补记进库时，页面会多一行 `ℹ` 说明：
  这一笔已交给移动止损接手（**常驻的 executor** 下一轮推进）。

判据与自动路径都在 `apps/executor`（`packages/core/src/risk-reattach.ts` 判据 +
`apps/executor/src/reattach.ts` 编排），因此控制面补的与 CLI 补的、自动挂的
**逐字一致**。

## 列表口径

标的列表取的是 **`symbols` 集合 ∪ `sync_state`**，与 `readGlobalSummary` 的计数口径一致。
只有状态和历史、没进集合的标的（典型来源：直接跑过 `data fetch`）不会被藏起来，
而是标成「未纳管」并给一个「加入集合」按钮。

## 设置页的四块

`#/settings` 里有四个互不影响的区块，各自管自己的取数与错误——一个失败不带走另一个：

- **交易所 API 凭据** —— 密文落库，页面只显示末 4 位、永不回显；改完要重启 executor。
- **飞书通知**（v0.8.0）—— 填 webhook 地址、开关、**逐项勾选要通知哪些内容**（每种一句话
  说明）、重复提醒间隔；地址同样**密文**落库、页面只显示末 4 位。
  另有一个「发送测试消息」按钮，能立刻确认通道通不通。
  改完**不必重启 executor**：它每轮对账时重新读一次设置。

  ⚠️ **勾选清单里有两项默认不勾**（v1.0.0）：「Agent 提示词」与「止盈止损档位提示词」——
  勾上之后，对应的进程每次调模型前会把**真正发出去的那一组消息**逐字推到群里，
  用来回答「模型为什么这么答」。它们带着行情与**账户权益**，因此默认关闭，
  要发得显式勾上（清单与文案由服务端下发，页面不自己抄一份）。

- **止盈止损策略** —— 全局默认 + 逐标的覆盖，页面显示「当前生效的是哪一层」。
  **止盈倍数只有一个**（v0.9.1 起）：它是「这次要卖的那部分，涨到离入场多远就卖」——
  减仓 0% 时卖全部，1–99% 时先卖那一部分（剩下的交给移动止损）。
  每个框下面都写明了「什么时候才生效」，「当前生效」那一栏也会显示当前是哪种形态。
- **模型接入**（v1.0.0）—— 填地址 / 模型名 / API 密钥 / 超时。密钥**密文落库**、
  页面只显示末 4 位、**永不回显**。面板显示「当前生效的是哪一份」
  （控制面这一份 / 配置文件 + 环境变量兜底）。

  ⚠️ **三个输入框一律不回填**：密钥不能回显，地址与模型名回填了会让人以为
  「保存」能覆盖掉别的档位。留空 = **保持原样**。

  ⚠️ **「清空密钥」与「清空控制面这一份」是两个不同的动作**：
  前者只是把密钥删掉（地址与模型还在），后者是**整份退回**配置文件 + 环境变量。
  两者混为一谈会让人以为模型还在跑。

  ⚠️ **「清空密钥」会连同「启用模型」一起关掉**：服务端不许「开着模型却没密钥」
  （那是一份跑起来才失败的配置），所以清空密钥时必须把开关一起关掉。
  页面的确认框写明了这一点。

  ⚠️ **主密钥没注入时，密钥状态显示「不知道」而不是「没配」**：
  读不到密文与确实没配是两件事，处置完全不同。主密钥没就绪时整个表单禁用。

四块都遵守同一条安全线：**写操作过同源校验**（`checkOrigin`），**读路径永远拿不到明文**。

## 界面

设计系统写在 [`ui/src/styles.css`](ui/src/styles.css)，两套主题**几何完全一致**
（切主题只换颜色、不换布局）。配色取两份参考的各一半：

- **Apple** —— 信息层级与留白节奏。字号有明确台阶，卡片靠「发丝线 + 极轻投影」分层
  而不是粗边框，顶栏固定在顶部并带一层毛玻璃，互斥选项（K 线周期、区间）用分段控件。
- **Pundi X** —— 深色终端的气质。暗色下用霓虹青做唯一强调色，数字与代码用等宽，
  标签是大写 + 字距的微型字，背景铺一层几乎看不见的网格。

响应式分三档：**≥1180px** 双栏（设置页左窄右宽）、**≤860px** 表格整体变成卡片列表
（`data-label` 提供行内标签，DOM 不复制表头）、**≤720px** 顶栏与导航拆成两层。
窄屏下顶栏只显示迁移**版本号**（完整迁移名在 `title` 里），否则一行放不下。

## 链上仓位页（`#/chain` 与 `#/chain/<仓位键>`）

这一页只回答三个问题：**现在值多少、赚没赚、去链上看哪里**。它是**两条路由**：

### 列表（`#/chain`）

一页是**卡片网格**（`repeat(auto-fill, minmax(280px, 360px))`），每张卡只放「一眼看完」的东西：
币对与仓位号、区间内外标签、**当前价值**、**浮动盈亏**（金额 + 百分比）、**区间尺**
（现价落在哪儿、离两边多远）、现价、已赚手续费、**当前 APY**、上次采样时间、APY 口径。

**整张卡是一个 `<a>`**（`href` 就是详情路由），点击走路由跳转而不是整页刷新。
列表只渲染摘要，重活全在详情页——一张卡塞十个数就等于没有重点。

### 详情（`#/chain/<仓位键>`）

五块：

1. **结论** —— 仓位身份 + 一句人话（在不在区间、浮盈浮亏多少、成本多少、年化多少）+ 六张指标卡；
2. **定价区间** —— 一把尺子：下界、上界、现价落在哪儿、离两边各多远；
3. **采样明细** —— **每一次采样一行**的表格（田字格）：采样时间 / 现价 / 区间内外 /
   当前价值 / 浮动盈亏 / 累计手续费 / 区块高度。**按时间倒序**（最新的在最上面），
   最多显示 100 条，总数照实写出来；
4. **链上查看** —— 区块浏览器（仓位 NFT / 池子 / 持有人 / 投入交易 / 两个代币）
   与流动性平台（这笔仓位 / 我的头寸）的跳转，**新标签页打开**；
5. **技术细节** —— 默认收起：地址、仓位键、L 值、上次轮询……

⚠️ **不画走势图**（2026-11-14 简化）：曲线把一页变成了流水账，而这一页要回答的是
「现在在不在区间里、赚没赚、去链上看哪里」。**采样明细用表格，不用曲线**——
采样是每 15 分钟一次的离散事实，曲线会连出一条**从来没发生过**的中间过程。
采样**照旧落库**（`chain_position_snapshot`），`/api/chain/positions/:positionKey/snapshots`
路由也还在。

链接与**当前 APY**都由**服务端**算好放进 DTO
（`packages/core/src/chain-links.ts` / `packages/core/src/chain-v3.ts` 的 `computeChainApy`）：
浏览器端不能 import `@trade-tool/core` 的运行时，而链接的拼法与年化的算式必须只有一份——
页面自己再算一次，改了口径只改了一边，另一边就成了**不一致的数字**（不会报错）。

APY 口径：**最近 7 天实收手续费 ÷ 投入成本，再年化**。算不出来时给 `null` + 一句人话原因
（没采样 / 成本为 0 / 窗口内手续费被领取过 / 窗口不到一天），不猜、不回落。

## 图表

**一律手写 SVG / CSS，不用图表库**（运行期依赖只有 react / react-dom / hono）：

- K 线：[`ui/src/components/CandleChart.tsx`](ui/src/components/CandleChart.tsx)。
  横轴按**时间**排布，缺一根就是空一根（按序号排会把空洞压成连续走势，R-23 明令禁止）。
- 状态分布：`OverviewCards.tsx` 里的 `.dist-bar`，一条按比例切开的横条。
- 链上仓位页**不画走势图**了：区间尺（CSS）取代了它，见上一节。

两个理由都还在：① 横轴必须按时间；② 图表库的 `ResponsiveContainer` 挂载时读
`ResizeObserver`，jsdom 里抛错会**中止同一次 commit 里剩下的全部 effect**——
首屏取数就此静默失效，页面永远停在「读取中」。

## 测试

```bash
pnpm --filter @trade-tool/web test
```

- `tests/server.test.ts` —— 路由与 `SyncError → HTTP` 映射，用纯替身，不连 PG 也不出网。
- `tests/jobs.test.ts` —— 作业生命周期、护栏与进度采样。
- `tests/rows.test.ts` —— 集合∪状态的并集逻辑（纯函数）。
- `tests/ui/App.test.tsx` —— jsdom 下挂载 `<App />`，断言它真的去取数并渲染真实数据。

UI 用例需要 `ResizeObserver`（`CandleChart` 量容器宽度会用），由
`tests/ui/setup.ts` 打桩。
